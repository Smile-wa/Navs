# 2026-11-15

## 天气组件修复 + 手机端折叠交互

### 天气获取失败的根因与修复
- 根因：`api.open-meteo.com/v1/forecast` 在国内网络下连接超时（curl HTTP 000 / 代理 CONNECT 超时），而 geocoding 子域可用；组件又没有请求超时，导致一直停在「正在获取天气…」/最终「天气数据暂不可用」。
- 实测可用：`wttr.in/<城市>?format=j1` 支持中文地名、拼音、经纬度，返回 `Access-Control-Allow-Origin: *`；Node 服务端直连也通（约 0.5s）。
- 改造为三源并行竞速（`Promise.any`）：① 同源 `/api/weather?city=` ② 浏览器直连 wttr.in ③ Open-Meteo（geocoding + forecast 兜底）。每个源独立超时 6.5~7s，静态托管无 Functions 时 `/api/weather` 返回 HTML 会被 JSON 校验挡掉并自动降级。
- 新增 `src/lib/weather.ts`：WWO weatherCode → 简体中文（含 149 烟霾）、WMO 码中文映射、内置城市经纬度表、统一 WeatherSnapshot、localStorage 1 小时缓存（网络全失败时显示缓存数据）、带中文原因的错误。
- 新增 `functions/api/weather.ts`（Cloudflare Pages Function，边缘代取 wttr.in，10 分钟缓存，挡掉 HTML 限流响应）；`vite.config.ts` 加同逻辑的 `/api/weather` dev 中间件。
- `WeatherWidget.tsx` 重写：数据来源标注、缓存/更新中标记、全失败时可点击重试（不再无限转圈）。后台 `Personalization.tsx` 说明文案改为多数据源。

### 手机端折叠
- `WeatherWidget` 新增 `collapsible` prop（Home 传 `isMobile`，即 `window.innerWidth < 768`）。
- 手机端默认仅 44px 圆形天气图标按钮（透明模式半透明深色底 + 模糊，卡片模式用 glass），不显示温度/详情；点击展开 190px 完整卡片，点击卡片外部或顶部 × 收起；切回桌面自动复位。
- `Home.tsx` 右上角容器移动端改为 `w-auto items-end`，避免透明大容器遮挡下层点击；桌面仍 `w-[240px]` 完整显示。
